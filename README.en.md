## Project Overview

RingTurn is an AI-powered music adaptation application that allows users to upload audio, set parameters, and describe their needs in natural language. The system automatically performs music analysis, melody extraction, MIDI generation, instrument arrangement, and audio rendering.

The project includes a frontend (React + Vite) and a backend (FastAPI + LangGraph).

This project is designed to run locally by default, with no user registration, login, or cloud account system. Therefore, instead of a traditional User module, we use Profiles to manage user-specific configurations. Profiles only store local preference data such as instrument choices and default parameters. They collect no personally identifiable information, which reduces deployment complexity and avoids additional privacy compliance overhead. For details, please refer to [Profile and Local Storage Design Document](./docs/设计说明文档：Profile模块与本地存储方案.md) (Chinese only).

### Project Background and Motivation

Currently, ordinary users face multiple obstacles when trying to adapt their favorite songs(for examples, into ringtones): **high barriers to professional software**, **uncontrollable AI generation tools**, and **high cost of human arrangers**.

RingTurn attempts to fill this gap by using external tools combined with LLM semantic understanding to mimic the workflow of a human arranger. It aims to provide a **free, controllable adaptation based on the original track** AI Agent, enabling non-professionals to easily obtain personalized ringtones.

## Backend Setup

### 1. Create a Virtual Environment

```
conda create -n ringturn python=3.10
conda activate ringturn
# or
cd backend
python -m venv venv
# Windows
venv\Scripts\Activate
# macOS / Linux
source venv/bin/activate
```

### 2. Install Dependencies

```
cd backend
pip install -r requirements.txt
```

### 3. Install FFmpeg

Even without FFmpeg, you can still process WAV audio.

> This project uses `FFmpeg` for audio format conversion and duration retrieval. Although the code can degrade gracefully (only WAV copying) when FFmpeg is missing, full functionality (e.g., MP3 ↔ WAV conversion, arbitrary format conversion) depends on FFmpeg.
> Check if it is installed:

```bash
ffmpeg -version # should output version info
```

**Conda installation (in virtual environment):**

```bash
conda install -c conda-forge ffmpeg
```

**Windows installation:**

1. Visit the [FFmpeg official website](https://ffmpeg.org/download.html) → Windows icon → Windows builds from gyan.dev.
2. Download `ffmpeg-release-full.7z` or `ffmpeg-release-full.zip`.
3. Extract to a local folder, e.g., `C:\ffmpeg`.
4. Add the `bin` folder path to your system `PATH` environment variable.

**Linux installation:**

```bash
sudo apt update
sudo apt install ffmpeg
```

### 4. Install FluidSynth

**Windows download:**
Visit the [GitHub releases page](https://github.com/FluidSynth/fluidsynth/releases) and download the latest version, e.g., `fluidsynth-v2.5.4-win10-x64-cpp11.zip`.

Due to limitations of `pyFluidSynth`, it is currently recommended to extract FluidSynth to `C:\tools\fluidsynth` and ensure `C:\tools\fluidsynth\bin` exists.
(We have noticed variations in different environments, so please adjust according to your actual situation.)

### 5. Download a SoundFont

To ensure the project runs properly, you need to download at least one SoundFont file and place it in the `backend/soundfonts` directory. For details, please refer to [SOUNDFONTS.md](./backend/SOUNDFONTS.md) (Chinese only).

### Common Issues

**Q: Audio generation fails with log showing `FluidSynth not found`**
A: Check if FluidSynth is installed and added to PATH.

**Q: Audio generation fails with log showing `FFmpeg not available`**
A: Install FFmpeg and verify `ffmpeg -version` works.

**Q: librosa warnings cause poor generation quality**
A: Use Python 3.10 for the virtual environment and avoid Python 3.13 due to compatibility issues.

## Reflections and Lessons Learned

### 1. Design vs. Implementation Gaps

During development, we encountered several mismatches between planning and reality:

- **UI Design**: We initially planned to use Figma/Penpot for detailed UI design, but the learning curve was steep and the gap between design and development was hard to bridge. Later, we switched to a "rapid prototype + iterative optimization during development" approach, adjusting interaction details based on actual implementation while ensuring usability.

- **Toolchain Effectiveness**: We planned to use advanced tools for precise music analysis. However, testing in a real Windows environment showed that many SOTA (State-of-the-art) models from papers either performed poorly or had poor environment compatibility, forcing us to adjust our adaptation strategy.

- **Development Plan**: We originally planned to focus on improving the `Arrange` node (introducing RAG knowledge base and allowing users to save adaptation skills) in the third iteration. However, because the preceding nodes (`Analysis` and `Extract_Melody`) were not solid enough, we spent a lot of time testing external tools, leaving insufficient time to complete the advanced features of the `Arrange` node before the semester ended.

### 2. Architectural Achievements

Despite the challenges, we made significant progress in architecture:

- **Dynamic Subgraph Refactoring**: We refactored core nodes (`Analysis`, `Extract_Melody`, `Arrange`) into dynamic subgraphs driven by JSON configuration, greatly improving system extensibility and flexibility (see [user tool management design document](./docs/用户工具管理功能设计.md) – Chinese only).

- **Product Features Implementation**: We successfully implemented historical conversation management, multi-round redo (feedback) mechanism, user preference statistics and injection, ensuring completeness at the interaction level.

### 3. Current Status and Future Outlook

Currently, RingTurn, constrained by the actual performance of external tools and development time, can only stably support **simple instrumental timbre replacement and basic tempo adjustments**. However, we have reserved ample room in the code structure for integrating more advanced source separation and music structure analysis models in the future, reflecting the core design philosophy of this course project: **"engineering and extensibility"**.
