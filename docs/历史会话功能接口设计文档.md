# 历史会话功能接口设计文档

## 1. 需求背景

### 1.1 功能目标

实现历史对话管理，支持侧边栏展示、查看、删除历史对话。

### 1.2 与现有 Task 的关系

- **Task**: 侧重于单次铃声生成任务的执行管理，包含状态、进度、结果等
- **Conversation**: 侧重于用户与 Agent 之间完整的多轮对话会话
- 一个 Conversation 可以包含多个 Task（优化迭代过程）
- 用户每次发起新的铃声请求时创建一个 Conversation

### 1.3 设计原则

1. 不修改原有的 task 接口
2. 历史会话显示的字段与 task 不同，包含用户请求内容和 Agent 响应内容
3. 支持多轮对话迭代优化

## 2. 数据模型设计

### 2.1 Conversation 表（会话表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String(36) | UUID 主键 |
| user_id | Integer | 关联用户（与 Task.user_id 一致） |
| title | String(200) | 会话标题（可从首条用户请求截取） |
| status | Enum | 会话状态：`active`（进行中）、`completed`（已完成） |
| created_at | DateTime | 创建时间 |
| updated_at | DateTime | 更新时间 |

### 2.2 ConversationMessage 表（消息表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer | 自增主键 |
| conversation_id | String(36) | 关联会话（外键） |
| role | Enum | 角色：`user`（用户）、`assistant`（Agent） |
| content | Text | 消息内容 |
| task_id | String(36) | 关联的任务 ID（可选，用于关联具体任务） |
| created_at | DateTime | 创建时间 |

### 2.3 ER 关系

```
User (1) ────── (N) Conversation (1) ────── (N) ConversationMessage
                      │
                      │ (可选关联)
                      ▼
                 Task (N)
```

## 3. 接口设计

### 3.1 创建会话

**POST** `/api/v1/conversations`

请求体：
```json
{
  "title": "钢琴风格铃声制作",     // 可选，不提供则自动截取首条消息
  "user_request": "帮我制作一个钢琴风格的铃声"  // 首次用户请求
}
```

响应：
```json
{
  "code": 200,
  "data": {
    "conversation_id": "uuid-xxx",
    "title": "钢琴风格铃声制作",
    "status": "active",
    "created_at": "2026-05-20T14:00:00Z"
  },
  "message": "会话创建成功"
}
```

### 3.2 获取会话列表

**GET** `/api/v1/conversations`

查询参数：
- `page`: 页码（默认 1）
- `page_size`: 每页数量（默认 20）
- `status`: 状态过滤（可选，`active` / `completed`）

响应：
```json
{
  "code": 200,
  "data": {
    "total": 50,
    "page": 1,
    "page_size": 20,
    "conversations": [
      {
        "conversation_id": "uuid-xxx",
        "title": "钢琴风格铃声制作",
        "status": "active",
        "message_count": 5,
        "last_message": "这是Agent的最后回复内容...",
        "created_at": "2026-05-20T14:00:00Z",
        "updated_at": "2026-05-20T14:30:00Z"
      }
    ]
  },
  "message": "获取成功"
}
```

响应：

## 4. Agent 消息记录集成

### 4.1 创建 Task 时自动创建 Conversation

在 `tasks.py` 的 `create_task` 接口中：

1. 如果是首次请求（非优化反馈），创建新的 Conversation
2. 如果是优化反馈（通过 feedback 接口），追加消息到现有 Conversation

### 4.2 Agent 执行过程中的消息记录

在 `agent_executor.py` 中：

1. Agent 开始执行时，记录 assistant 消息（包含任务计划）
2. 每个步骤完成时，记录思考过程
3. 任务完成时，记录最终结果摘要

### 4.3 消息内容格式

**用户消息（role: user）**：
```
{user_request}
参数：{instrument}, {duration}秒, {tempo} BPM
```

**Agent 消息（role: assistant）**：
```
任务已开始执行
计划：{plan}
[后续逐步更新执行状态和思考过程]
最终结果：{final_audio_url}
```

## 5. 数据库表 SQL

```sql
-- Conversation 表
CREATE TABLE IF NOT EXISTS conversations (
    id VARCHAR(36) PRIMARY KEY,
    user_id INTEGER NOT NULL,
    title VARCHAR(200),
    status VARCHAR(20) DEFAULT 'active',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- ConversationMessage 表
CREATE TABLE IF NOT EXISTS conversation_messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    conversation_id VARCHAR(36) NOT NULL,
    role VARCHAR(20) NOT NULL,
    content TEXT NOT NULL,
    task_id VARCHAR(36),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE,
    FOREIGN KEY (task_id) REFERENCES tasks(id)
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_conversation_user_id ON conversations(user_id);
CREATE INDEX IF NOT EXISTS idx_conversation_status ON conversations(status);
CREATE INDEX IF NOT EXISTS idx_message_conversation_id ON conversation_messages(conversation_id);
```

## 6. 实现计划

### 阶段一：基础数据结构
1. 创建 `Conversation` 和 `ConversationMessage` 模型
2. 创建对应的 Pydantic Schema
3. 创建 `conversations.py` API 端点

### 阶段二：集成到现有流程
1. 修改 `create_task` 接口，创建 Conversation
2. 在 `agent_executor` 中记录 Agent 消息
3. 修改 `submit_feedback` 接口，追加消息到 Conversation

### 阶段三：WebSocket 增强（可选）
1. 在 WebSocket 中推送会话消息
2. 支持实时消息更新

---

## 7. 注意事项

1. **向后兼容**：不修改现有 Task 接口，保持向后兼容
2. **数据隔离**：会话数据按 user_id 隔离，确保用户只能访问自己的会话
3. **级联删除**：删除会话时自动删除关联的消息
4. **性能考虑**：列表查询时使用索引优化，避免全表扫描

## 8. 前端开发指南

### 8.1 API 调用说明

#### 8.1.1 Task 模块变更

**POST `/api/v1/tasks` 创建任务接口已更新**

响应新增 `conversation_id` 字段：

```json
{
  "code": 200,
  "data": {
    "task_id": "task-uuid-xxx",
    "conversation_id": "conv-uuid-xxx",  // 新增字段
    "status": "pending",
    "created_at": "2026-05-20T14:00:00Z"
  },
  "message": "任务创建成功"
}
```

**前端建议**：
- 创建任务后保存 `conversation_id`，用于后续查询会话详情
- 不需要单独调用 `POST /api/v1/conversations`，任务创建时已自动创建会话

#### 8.1.2 Conversation 模块（新）

**推荐使用的工作流程**：

```typescript
// 1. 创建任务时获取 conversation_id
const response = await api.post('/api/v1/tasks', {
  user_request: '帮我制作钢琴风格铃声',
  source_type: 'upload',
  source_value: 'file-id-xxx',
  params: { instrument: 'Acoustic Piano', duration: 30, tempo: 120 }
});
const { task_id, conversation_id } = response.data;

// 2. 查询会话列表（侧边栏）
const listRes = await api.get('/api/v1/conversations', {
  params: { page: 1, page_size: 20 }
});

// 3. 进入会话详情页面时，获取完整消息
const detailRes = await api.get(`/api/v1/conversations/${conversation_id}`);

// 4. 通过 WebSocket 订阅任务进度
// ws://host/ws/chat/{task_id}
// 任务完成/失败时，可通过 conversation_id 查看完整会话历史

// 5. 删除会话
await api.delete(`/api/v1/conversations/${conversation_id}`);
```

### 8.3 WebSocket 实时更新

任务执行过程中，推荐使用 WebSocket 获取实时进度：

**连接**：`ws://host/ws/chat/{task_id}`

**接收消息格式**：

```typescript
// 状态更新
{
  "type": "status_update",
  "task_id": "xxx",
  "status": "executing",
  "current_subtask": "arrange",
  "subtask_progress": 60,
  "thinking_process": [...],
  "timestamp": "2026-05-20T14:05:00Z"
}

// 任务完成
{
  "type": "completed",
  "task_id": "xxx",
  "audio_url": "/static/xxx.mp3",
  "duration": 30,
  "timestamp": "2026-05-20T14:10:00Z"
}

// 任务失败
{
  "type": "failed",
  "task_id": "xxx",
  "error": "处理失败原因",
  "timestamp": "2026-05-20T14:10:00Z"
}
```

**前端建议**：
- 任务创建后立即连接 WebSocket
- 收到 `completed` 或 `failed` 消息后，可调用 Conversation API 获取完整会话历史
- 保留轮询作为 WebSocket 连接失败时的降级方案

### 8.6 注意事项

1. **conversation_id 存储**：建议在前端本地存储（如 localStorage）保存最近使用的 `conversation_id`，方便快速恢复会话
2. **消息渲染**：Assistant 消息可能包含换行符 `\n`，渲染时需处理
3. **长消息截断**：会话列表中的 `last_message` 字段已截断至 100 字符
4. **状态同步**：任务完成后，前端应刷新会话详情以获取 Agent 的完整回复
5. **错误处理**：WebSocket 断开时自动降级到轮询模式
