# 引言
由于我们的软件特性（每一个节点必须保有部分工具或工具组合以保证可用性），我们不能完全放开工具选择。我们的目标是：
1. 允许用户在前端自由选择**部分工具**（但不能完全放开，以保证核心流程可用）。
2. 后端能够根据用户选择的工具动态调整各节点的工具集和提示词，并保证默认能力回退。
3. 架构具备可扩展性，未来可引入更多工具，且 Agent 能更自主地调用工具（而非完全写死链条）。

当前 RingTurn 项目采用“固定节点 + 硬编码工具列表”的架构（如 `nodes/analyze_structure.py` 中的 `step_tools` 和提示词）。这种方式虽然简单可靠，但存在以下问题：
- **扩展性差**：新增工具需要修改节点代码和提示词，易出错。
- **用户不可控**：用户无法根据自己的偏好（如“追求速度”或“追求质量”）选择工具。
- **工具链单一**：难以处理复杂工具间的依赖（如人声分离必须与 Basic Pitch 搭配）、冲突（如同类工具二选一）、优先级（首选失败时降级）。虽然在工具链简单的情况下能够基本处理，但一旦引入更多工具就会变得非常复杂。

综上，决定设计一套基于LangGraph的工具管理机制，实现：
1. **用户可配置**：前端提供场景化选项（普通模式）和专家模式（自由选择工具）。
2. **工具链声明式管理**：通过元数据和图结构定义工具的依赖、优先级、适用场景。
3. **Agent 自主决策**：LLM 根据用户偏好和实时状态动态选择工具调用顺序。
4. **可扩展**：新增工具只需注册元数据，无需改动节点核心逻辑。

## 技术选型：LangGraph
考虑到我们的项目原本就基于LangGraph框架，且LangGraph 是 LangChain 生态中专门用于构建有状态、多步骤 Agent 工作流的框架，使用其处理外部工具有以下优势：
- **声明式控制流**：通过 `add_edge`、`add_conditional_edges` 明确工具执行顺序，从根本上避免 LLM 调用顺序出错。
- **工具节点化**：`ToolNode` 将工具作为图节点，状态自动传递，无需手动管理参数。
- **可观测性**：内置流式输出和检查点，方便调试。
## 具体设计
已在项目中使用的功能：
- 基础图结构（`StateGraph`、节点、边）
- 检查点（`SqliteSaver`）
- ReAct Agent（在节点内部使用 `create_react_agent`）

本设计将扩展使用：
- **条件边**：实现工具选择的路由（如根据用户偏好跳转到不同工具子图）
- **ToolNode**：标准化工具执行
- **子图**：将每个任务节点内部工具链封装为子图
- **人机协同**：预留工具冲突时人工介入的节点
### 示例
以 `analyze_structure_node` 为例，使用LangGraph子图+ToolNode处理工具（与最终实现无关，仅做示例）：
```python
# 子图定义（伪代码）
analysis_subgraph = StateGraph(AnalysisState)

# 添加工具节点（ToolNode）
analysis_tools = ToolNode([get_bpm_tool, get_key_tool, ...])
analysis_subgraph.add_node("tools", analysis_tools)

# 添加 LLM 决策节点
analysis_subgraph.add_node("decider", llm_node)

# 条件边：decider 决定调用哪些工具
analysis_subgraph.add_conditional_edges("decider", tools_condition)
analysis_subgraph.add_edge("tools", "decider")  # 工具执行后返回决策节点

# 最终输出条件
def should_finish(state):
    if state.get("analysis_complete"):
        return "end"
    return "decider"

analysis_subgraph.add_conditional_edges("decider", should_finish)
```

### 工具解析器（ToolResolver）

在 Agent 执行前，根据用户偏好和工具元数据，生成最终工具列表。
**工具元数据定义示例**（每个节点独立维护）：
```python
# app/agent/node_tools/extract_melody_meta.py
NODE_TOOL_META = {
    "extract_melody_basic_pitch": {
        "display_name": "Basic Pitch 旋律提取",
        "description": "深度学习模型，精度高，适合人声",
        "characteristics": ["high_accuracy", "vocal"],
        "priority": 5,
        "requires": ["separate_vocals"],
        "conflicts": ["extract_melody_librosa"],
        "suggests": ["filter_short_notes", "quantize_notes"]
    },
    "extract_melody_librosa": {
        "display_name": "Librosa 旋律提取",
        "description": "传统信号处理方法，速度快，适合纯音乐",
        "characteristics": ["fast", "instrumental"],
        "priority": 3,
        "requires": [],
        "conflicts": ["extract_melody_basic_pitch"]
    },
    "separate_vocals": {
        "display_name": "人声分离",
        "description": "使用 Demucs 分离人声，耗时较长",
        "characteristics": ["preprocessing"],
        "priority": 4,
        "requires": [],
        "suggests_precede": ["extract_melody_basic_pitch"]
    }
}
```

**解析逻辑（仅作示例，与最终实现无关）：**
```python
def resolve_tools(node_name: str, user_prefs: dict) -> List[str]:
    meta = NODE_TOOL_META[node_name]
    mode = user_prefs.get("mode", "scene")
    
    if mode == "scene":
        scene = user_prefs.get("scene", "balanced")
        # 场景映射到工具标签
        if scene == "vocal":
            candidates = ["extract_melody_basic_pitch"]
        elif scene == "instrumental":
            candidates = ["extract_melody_librosa"]
        elif scene == "fast":
            candidates = ["extract_melody_librosa"]  # librosa 更快
        else:  # balanced
            candidates = ["extract_melody_basic_pitch"]
    else:  # expert mode
        enabled = set(user_prefs.get("explicit_enabled", []))
        disabled = set(user_prefs.get("explicit_disabled", []))
        candidates = enabled - disabled
    
    # 处理依赖：添加 requires 中的工具
    for tool in list(candidates):
        candidates.update(meta[tool].get("requires", []))
    
    # 处理冲突：按优先级保留最高
    # ...（实现略）
    
    return list(candidates)
```

### 节点动态子图生成
每个节点（如以下示例）不再硬编码工具列表，而是根据解析结果动态创建子图：

```python
async def extract_melody_node(state: AgentState, db: Session, tools) -> None:
    user_prefs = state.get("tool_preferences", {}).get("extract_melody", {})
    tool_names = resolve_tools("extract_melody", user_prefs)
    
    # 从全局注册表获取工具对象
    step_tools = [get_tool_by_name(name) for name in tool_names]
    
    # 动态构建子图（使用 ToolNode + 条件边）
    sub_graph = StateGraph(AgentState)
    sub_graph.add_node("tools", ToolNode(step_tools))
    sub_graph.add_node("decider", llm_decision_node)
    sub_graph.add_conditional_edges("decider", tools_condition)
    sub_graph.add_edge("tools", "decider")
    # ... 设置入口和出口
    
    # 执行子图
    final_state = await sub_graph.ainvoke(state)
    state.update(final_state)
```

### 错误处理
- **缺失必要工具**：如果解析后的工具列表为空或缺少 required 工具，抛出 `ToolResolutionError`，任务状态变为 `failed`，`error_message` 提示“节点 X 缺少必要工具，请检查工具偏好设置”。
- **工具执行失败**：在子图中通过条件边实现重试或降级。例如，Basic Pitch 失败后自动调用 Librosa。

## 前端设计
工具管理功能放置在 Dashboard 页面的“工具偏好”区域（预计位于音乐偏好下方）。Dashboard 尚未实现，本设计给出独立组件 `ToolPreferencesPanel`的示例（不保证最终同样实现）。
### 两种模式
**模式一：场景选择（必须实现）**
提供三个场景卡片，用户选择后自动生成工具组合：

| 场景     | 说明             | 适用工具示例                    |
| ------ | -------------- | ------------------------- |
| 人声旋律优先 | 适合歌曲，高质量提取人声旋律 | Basic Pitch + 人声分离 + 音符过滤 |
| 纯乐器改编  | 适合纯音乐，速度快      | Librosa + 音符过滤            |
| 最快速度   | 牺牲部分质量，优先响应速度  | Librosa（无过滤）              |

用户选择场景后，系统自动保存为 `{ mode: "scene", scene: "vocal" }`。
**模式二：专家模式（可选）**
以分类表格形式展示每个节点的工具，提供开关，允许用户完全自定义管理工具。
